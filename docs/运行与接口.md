# 运行与接口

## 本地运行

复制根目录 `.env.example` 为 `.env`，填写模型配置，在仓库根目录执行 `python -m pr_harness`，或 PowerShell 的 `.\Start-PRHarness.ps1 -Local`。使用虚拟环境中的 Python。模板监听 http://127.0.0.1:18080/，实际地址由配置决定。

`PR_HARNESS_DB_PATH` 默认为启动工作目录的 `pr_harness.db`；PowerShell 启动脚本会固定工作目录。进程环境变量优先于 `.env`，修改配置后重启应用。

自动审查启动器会建立隧道并管理目标仓库 Webhook，详见 [GitHub 自动审查](GitHub-PR自动审查.md)。

## 常用接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/health` | 服务状态与配置检查 |
| POST | `/v1/auth/login` | 开启认证时获取 Bearer Token |
| POST | `/v1/reviews` | 同步创建审查 |
| POST | `/v1/reviews?async=true` | 入队并返回 task_id |
| GET | `/v1/tasks/{id}` | 状态、轨迹和报告 |
| GET | `/v1/tasks/{id}/report` | Markdown 报告 |
| POST | `/v1/tasks/{id}/feedback` | 提交反馈 |
| POST | `/v1/tasks/{id}/resume` | 从持久化状态恢复 |
| POST | `/v1/tasks/{id}/fix` | 申请修复与测试验证 |
| POST | `/webhooks/github` | 接收经过签名校验的 PR 事件 |
| POST | `/v1/skills/reload` | 重载磁盘 Skill |
| GET | `/metrics` | 运行指标 |

具体请求字段与完整路由以 `pr_harness/api/main.py` 为准。后端只有 agentic 审查 API 模式，实际审查需要可用模型；内部规则审查器用于工具与测试。`/health` 不验证模型账号额度或回答质量。

`skills/` 下的 SKILL.md 提供领域规范，工具执行由 `tooling/` 和 `core/runtime.py` 负责；不能仅添加提示词文件就获得新的外部工具能力。
