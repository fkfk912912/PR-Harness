# 日常启动与审阅指南

## 启动与停止

首次安装、创建虚拟环境与配置模型见 [项目 README](../README.md)。在仓库根目录执行：

```powershell
.\Start-PRHarness.ps1 -Local
```

打开 `.env` 中配置的端口，模板默认 http://127.0.0.1:18080/。按 Ctrl+C 停止本地服务。VS Code 的“运行和调试”提供 **PR Harness** 与 **PR Harness: Stop** 两个受管理的 GitHub 会话入口；使用前先完成 [GitHub 配置](GitHub-PR自动审查.md)。

```powershell
.\Start-PRHarness.ps1 -Check
.\Start-PRHarness.ps1 -Repository owner/repository
.\Start-PRHarness.ps1 -Stop
```

`-Check` 会检查模型配置、资源文件和 GitHub 凭据，适合已安装 GitHub CLI 的集成环境；它不执行实际模型请求。首次连接目标仓库必须提供 `-Repository`，后续默认读取本机保存的仓库记录。

## 手动审阅

1. 打开管理台，按部署配置登录。
2. 填入仓库名称和 diff，选择需要的审查设置并提交。
3. 查看任务状态、问题证据、涉及行号、修复建议及测试建议。
4. 核对结果后提交反馈，供后续检索和候选策略评测使用。

报告输出受模型、工具证据、任务预算及门禁影响。出现失败时查看任务错误与服务日志；健康检查通过只说明服务能响应。

## 自动审阅与修复

GitHub 启动器在线时，目标仓库 PR 事件会触发审查并允许报告回评。隧道每次启动可能更换地址，由启动器更新 Webhook。

申请修复前配置 `PR_HARNESS_REPAIR_TEST_COMMAND` 为目标仓库的测试命令，并核对仓库访问权限。修复过程依赖实际的前后测试证据；结果和 Draft PR 应由使用者继续审阅。

## 状态与排障

`validation/github-webhook/status.json` 保存仓库、Webhook 编号、进程信息与地址，供受管理会话恢复和停止使用，不提交到 Git。模型请求失败可检查密钥、额度与服务商；端口被占用时先确认已有实例并使用其管理台，或停止对应实例后重启。

接口清单见 [运行与接口](运行与接口.md)，测试和配置细节见 [开发指南](development.md)。
